# 主 Agent 与批改子 Agent 实施计划

**Goal:** 每组材料由一个主会话处理，使用真实审核和批改 Sub Agent，支持单独建库以及 OCR 定位标注。

**Architecture:** Claude Agent SDK 主会话通过受限 MCP 工具读图及持久化阶段产物，通过原生 Agent 工具调用两个子 Agent。后端检查调用者、阶段版本、答案审核与 OCR 块引用；绘图由程序执行。

**Tech Stack:** Python/FastAPI、Claude Agent SDK、DeepSeek OCR、Pillow、现有原生 JavaScript 前端。

## 已确认的行为

- 一组材料只包含一位学生；允许仅试卷和参考答案的 prepare 模式。
- 主 Agent 独立解题并保留老师答案；answer-reviewer 独立验算。老师答案冲突待人工确认。
- AI 答案允许一次修正再审核，仍有分歧则待确认；批准答案才可批改。
- student-grader 自行读学生原图、抄录作答并判定，识别遗漏不能直接当空白。
- OCR 在预处理后先识别全部上传页；原始结果缓存，文字块、编号与坐标共享给主 Agent 和两个子 Agent。批改子 Agent 同时关联学生答案块，主 Agent 最后检查；后端计算坐标。
- 无可靠坐标不落笔、不猜位置、不回退题干；保留已有判分。
- 主 Agent、子 Agent 使用当前模型配置。新批改统一使用 DeepSeek OCR。
- 已建库试卷保留原题图片，以支持只上传答题卡。
- 队列、状态、SSE、重试、人工改判、统计、PDF 和历史记录继续可用。

## 验收

每题可追溯原题、标准答案审核、学生作答、批改理由与 OCR 块。未经审核不可批改，争议题不自动落笔，无法定位不丢失判分。模拟接口验证真实 SDK Agent 工具调用；有可用测试凭据时再做 DeepSeek 付费接口联调，不使用真实学生数据。

## 用户要求的独立审查与修复（2026-11-16）

- 使用一个审查子 Agent，先提供可复现问题，修复后由同一 Agent 复审；复审未发现新的高置信缺陷。
- 修复前导小数 `.5` 被当作 `5` 的审核与 OCR 匹配错误；保留有效 OCR 坐标，使待复核题经人工改判后能恢复标记。
- 新标准答案图片不能因为参考答案未提取就跳过审核；重批明确使用老师在试卷库最新确认的答案，原旧文件不会覆盖。
- 未明确选卷时，自动复用增加逐题原图 SHA 校验；相同题干但不同配图独立建卷审核，避免污染旧卷答案。不同扫描件可显式选择已备试卷继续复用。
- 各阶段统一规范题号，防止带前后空格的编号通过验证后在后续匹配时失败。
- 新增 10 个回归场景；完整测试（包含真实 SDK 的本地模拟联调）188 passed，前端 45 passed，Ruff F、JavaScript 语法与差异空白检查通过。

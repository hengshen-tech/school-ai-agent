# A道工作台 · AI 作业批改与学情分析

添加试卷、可选的标准答案和一位学生的多页作答（PDF / PNG / JPG / WebP），点击「开始批改」后完成 **阅读 → 判分 → 标注**，再用 Pillow 把 ✓ / ✗ 画回卷面。
视觉模式保留复核 Agent；OCR 模式直接使用学生答案文字块的坐标，省去整轮视觉复核。
DeepSeek 接口和 Key 可用时默认选择 **DeepSeek OCR 辅助**，也可在开始前切换视觉识别。模型通过 **Claude Agent SDK** 调用，默认 **DeepSeek V4.1 Flash**，所有阶段显式开启思考并使用 **high**。

## 启动

```bash
./start.sh              # 构建并启动，就绪后打印访问地址
./start.sh stop         # 停止；另有 restart / logs / status
./start.sh local        # 不用 Docker，用本机 Python 直接运行（开发用）
```

端口、访问口令等可以写在同目录的 `.env` 里（`PORT=8001`、`APP_PASSWORD=...`、`PIP_INDEX_URL=...`）。
也可以直接用 compose：

```bash
docker compose up -d --build
# 国内网络构建慢的话：
# docker compose build --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple && docker compose up -d
```

打开 <http://localhost:8001> → 「模型设置」填写后点「测试连接」：

| 项 | DeepSeek V4.1 Flash 的填法 |
| --- | --- |
| 模型名称 | `deepseek-flash` |
| 接口地址 | `https://api.deepseek.com/anthropic`（Anthropic 兼容地址，结尾不要带 `/v1`） |
| API Key | DeepSeek 平台的 Key |

换成其他支持图片输入、提供 Anthropic 兼容接口的模型，只需改这三项。也可以用环境变量 `LLM_MODEL / LLM_BASE_URL / LLM_API_KEY` 预置。
数据（试卷库、批改记录、设置）都在 `grader-data` 卷里。

## 功能一览

| 模块 | 做什么 |
| --- | --- |
| **批改** | 同一学生的多份材料统一提交，点击开始才处理；实时显示 Agent 进度；人工改判后标注图立即重画；批改后的试卷可**下载 PDF** |
| **批改队列** | 返回、切页、刷新、关闭浏览器后继续批改；侧栏显示运行数量，首页展示运行列表；随时重新进入查看进度与原图 |
| **任务中心** | 一次作业 / 测验 = 一个任务。按学生添加材料、开始批改，查看已交 / 未交 / 批改中 / 待复核，逐人下载 PDF |
| **班级管理** | 班级、花名册（批量粘贴"学号 姓名"）。解析 Agent 读出卷面姓名 / 学号后自动归档到学生，匹配不上的可手动指定 |
| **学生档案 · 成长档案** | 历次正确率曲线、知识点掌握、错因分布、错题本；学情分析 Agent 写成长评语并出"错一练三"同类练习 |
| **学情报告** | 班级或单次任务：讲评清单（按正确率排序 + 典型错误答案 + 答错学生）、知识点掌握、分层名单、需要关注的学生；AI 讲评与分层建议；导出 CSV、打印 |
| **试卷库** | 每套试卷的题目、标准答案、知识点，可编辑 |

所有统计都由已保存的批改结果实时计算（`backend/app/analytics.py`），不调用模型；只有"评语 / 讲评建议"才调用学情分析 Agent，且统计数据没变时直接返回上次生成的内容。
计分口径：正确 1、部分正确 0.5、错误 0，**待复核的题不计入**，老师改判后才计入。

参考主流智慧作业产品和学校实践后加入的点：班级共性错题讲评、个人知识画像与错题本、错一练三、分层名单、需关注学生预警、提交率跟踪、保留人工复核与改判。

## 输入与 Agent 分工

选择或拖入文件只会加入「待开始」列表，可以追加、移除或指定用途，点击「开始批改」才上传和调用模型。
一次开始对应一位学生；可只传一张作答照片，也可同时传试卷、标准答案和多张学生作答图，PDF 按页展开。
限制为最多 20 个文件、单个 40MB、合计 200MB、总计 40 页。页数在渲染 PDF 前预检。

材料默认「自动识别」。整组图片、来源页码和 OCR 结果一次交给解析 Agent，由 Agent 识别材料用途、对应题目与学生作答、
提取标准答案；程序不按文件名或硬编码题号拼接业务关系。必要时可在开始前指定「试卷 / 标准答案 / 学生作答」。
标准答案可缺省，由解题 Agent 求解；独立答题纸缺题干时应一起提供试卷。不同学生应分别开始。

OCR 提供文字块和坐标；Agent 理解题目、解题、判分并返回学生答案页码与 OCR 块编号；程序负责后台执行和绘制标记。
参考试卷和标准答案保留供查看，不作为学生答卷计分或写上批改标记。PDF 下载只导出学生作答页。
不同任务的待开始材料和答案文本独立保存，可在首页切换草稿；草稿仅在当前页面内存中保留，刷新前应完成提交。

## 执行流程

```
点击开始 ─► 保存整组材料与用途 ─► 预处理（PDF→逐页 PNG、EXIF 矫正）
     ─► DeepSeek OCR    OCR 模式：带编号的文字块 + 坐标                              ocr.json
     ─► 解析 Agent      整组图片 → 材料用途 / 题目 / 学生答案 / 参考答案与坐标编号    materials.json / layout.json
     ─► 试卷库匹配       题干指纹 + 文本相似度，判断是不是同一套试卷
     ─► 标准答案 Agent   只在新试卷时运行，给出答案和知识点，写入试卷库（paper.md + answers.json）
     ─► 批改 Agent      先做确定性比对，比不出来的才交给模型                          grading.json
     ─► 位置检查        OCR 模式：程序校验答案块；视觉模式：复核 Agent 逐题核对       verified.json
     ─► 标注            Pillow 画 ✓ ✗ ½ ?，OCR 模式直接用答案文字块坐标落笔
     ─► 归档            按卷面姓名 / 学号匹配花名册，进入学生档案与学情统计
（按需）学情分析 Agent  把统计数据写成讲评建议 / 成长评语 / 同类练习
```

每个 Agent 都是一次 `ClaudeSDKClient` 会话（`backend/app/agents.py`）：关闭了 Claude Code 的内置工具，
视觉模式的复核 Agent 额外挂了一个进程内 MCP 工具 `zoom_region`，可以自己决定放大原图的哪一块再下结论。
OCR 模式不启动复核 Agent，页面显示「OCR 位置检查」，这一步不调用模型。

## 后台批改与进度

上传成功后，批改由服务端独立执行，页面上的「返回」只关闭进度订阅。可以继续上传其他作业，
从侧栏「批改队列」、首页的「正在批改」或任务中心的队列重新进入；详情地址可在刷新后恢复。
后台完成不会抢占当前页面。预处理完成后即可查看原图，无需等待判分完成。

右侧每个阶段可展开/折叠，保留页数、题数、工具调用、重试和耗时记录；展开「模型原始输出」可按页或批次查看各次调用的生成文本，并行输出不会混在一起。
模型内部思考只显示活动状态，不展示推理正文；只有完整解析成功的 JSON 才参与业务处理。
结果里的「耗时与模型调用」可查看阶段耗时、模型等待名额、首个输出、总调用时间和可用 token 用量。
各阶段可能并行，阶段耗时不能直接相加当作总时间。

单次 Agent 调用默认最多等待 **30 分钟**（`AGENT_TIMEOUT_S=1800`）；SDK 请求与外层调用使用同一上限。
等待模型并发名额不占用这 30 分钟；整份作业包含多次调用，因此这不是全卷的总时限。
可通过环境变量调整，修改后需重启服务；Docker 部署需重新创建容器以载入环境配置。

任务快照和进度日志保存在每份记录的 `job.json` 与 `events.jsonl`。服务重启后，未完成任务标为「已中断」，
可点击「重试」使用原件和原输入创建新任务；不自动重复付费调用。任务快照保留模型配置但不保存 API Key，重试使用当前 Key。
本实现使用单进程 Uvicorn；不要配置多个 worker 同时读写这一份数据目录。

## DeepSeek OCR 接口（上传时可选）

在批改首页或任务中心开始前选择识别方式：接口可用时默认「DeepSeek OCR 辅助」，会额外调用
`POST /v1/tools/ocr`（按页另计费）。辅助模式也会让视觉模型看图，不是只用 OCR 文字判卷。
接口地址是 `https://*.deepseek.com` 且填了 Key 时才可选择；不可用时回退视觉识别。设置页旧开关保留历史配置，不控制新上传区的选择。
整组材料逐页并行 OCR，再由解析 Agent 整体理解；旧单图接口仍兼容。OCR 接口只提供保活换行与最终 JSON，页面等待期间显示具体页码，返回后展示文字。

OCR 返回的文字块自带 0–1000 归一化坐标。解析 Agent 返回学生答案的 `answer_block_ids` 和本题题干的
`question_block_ids`。有答案块时直接复制 OCR 坐标，多块答案取组合边界，在答案旁绘制标记。
OCR 文字与学生答案抄录的格式或内容差异不再触发一致性提示，也不再阻止标注。

没有明确答案块、无效编号、同一答案块被多题使用时，改在各自的题干 OCR 块旁标注。
题干也没有 OCR 坐标时使用解析 Agent 提供的 `question_bbox`，不增加复核模型调用。
空白答案也可在题目旁画错号；看不清或批改把握不足等判分问题仍保留「待复核」。
只有答案、题目都没有可用位置时才保留未定位提示。人工改判使用同样的位置绘制 ✓ / ✗ / ½。

原始识别文本与文字块保存在每份记录的 `ocr.json`。已有 OCR 结果打开、读取批改图或人工改判时，
会按保存的 OCR 数据补绘标记、清除旧的位置文字差异提示，无需重新调用 OCR 或批改模型。
补绘版本保存在 `annotation_version`，后续查看直接复用。旧记录若缺少原图或可恢复的坐标，仍需重新批改。

上传区「我有标准答案」可填写答案文本，或将 PDF / 图片加入列表并指定为标准答案；选择文件不会立即调用 OCR。

没有集成 DeepSeek 的「文档解析」（Files API）：它把文件解析后以 `file_id` 挂进对话，解析结果拿不到、也没有坐标，
而本项目需要坐标并且已经直接发图片；读答案文件这个用途 OCR 接口已经覆盖。

## 两层缓存（同一套试卷不重复算答案）

1. **同一组材料**（各文件内容、顺序、用途及来源文件名相同，且班级、任务、指定学生和识别方式一致；旧单文件接口保持兼容）：直接返回上次的批改结果，不调用模型。试卷库答案被改过、或结果已改归到其他班级/指定学生后，这层缓存不再复用原归档结果。
2. **同一套试卷**（不同学生、不同扫描件）：解析后用题干做指纹，再用文本相似度兜底（阈值 `PAPER_MATCH_THRESHOLD`，默认 0.85）。
   命中后复用试卷库里的标准答案，跳过解题 Agent；页面上会显示「命中试卷库 · 未重新计算答案」。
   全班同时上传一套新试卷时，后续作业等待并复用第一份正在生成的答案；不同试卷的解题不会被全局锁阻塞。

文件级缓存区分识别方式；切换识别方式会重新识别，但仍可复用同套试卷的标准答案。

试卷库里每套试卷保存 `paper.md`（题目 + 答案，方便人读）、`paper.json`、`answers.json`（机器用）。
老师可以在「试卷库」页面修改答案，然后在批改记录里点「重新批改」；上传时也可以直接粘贴标准答案，以老师的为准。
修改标准答案会同时清除旧答案的等价写法，避免旧值继续被直接判对。
试卷匹配、同卷并发复用和答案对齐都会核对数学结构；数字、运算符、括号或变量变化时不套用原答案。

## 相对原方案的改动

- **坐标用 0–1000 归一化**，不让模型报像素值。模型看到的是缩放后的图，报像素坐标必然错位；归一化后由代码换算回原图。
- **按识别方式检查位置**：视觉模式保留全题裁图复核；OCR 模式直接用实际答案文字块坐标，省去复核 Agent。
- **不静默通过**：答案看不清、复核读到的内容和解析不一致、批改把握不足、缺标准答案、AI 对答案没把握，都会标为「待复核」（卷面画 ?）；
  位置不明确的题不在卷面落笔，只在右侧列表里提示。老师可以一键改判，已有明确位置的标注图会立即重画。
- **新增标准答案 Agent 和试卷库**（原方案假设答案已经存在）。
- **JSON 为主数据，Markdown 为副产物**，与原方案一致。

试卷匹配除了题干相似度，还要求题干里的数字序列完全一致（短试卷和题干指纹命中也要检查）：只改了数字的 A/B 卷不会被当成同一套；
单道题的数字和试卷库里不一致时，这道题不套用答案，转人工复核。

## 注意

- API Key 以明文保存在数据卷的 `settings.json` 里。默认没有登录；设置环境变量 `APP_PASSWORD` 后访问需要口令（HTTP Basic，用户名随意）。
  即便设置了口令，也建议只在本机或内网使用，对外请放在 HTTPS 反向代理后面。
- 系统里有学生姓名、学号和成绩，属于个人信息，请按学校的数据管理要求保管数据卷。
- 数据存成 JSON 文件，统计时会扫描全部批改记录，适合单个老师或一个年级的量（几千份以内）；更大规模需要换成数据库。
- `MAX_PARALLEL_JOBS`（默认 2）控制同时批改的份数，受模型接口的并发限额约束。
- `MAX_PARALLEL_MODEL_CALLS`（默认 3）限制所有批改共享的模型调用并发；批改/视觉模式全题复核按批并行，所有模型阶段保持 `high`。
- 试卷内容会发送到你配置的模型服务商。
- AI 生成的标准答案可能出错，第一次批改一套新试卷后，建议到「试卷库」核对一遍答案。

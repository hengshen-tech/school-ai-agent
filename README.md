# A道工作台 · AI 作业批改与学情分析

每组上传材料直接交给 **一个 Claude Agent SDK Agent**。主 Prompt 使用用户提供的 `exam-grading`：完整看图 → 按需裁剪/放大 → 识别手写 → 独立解题 → 判分 → 自主复核 → 返回坐标。新任务不使用 DeepSeek OCR，也不先调用另一个模型分类材料。

同一 Agent 可用 SDK 内置 Read 和受限 Bash 读取原图、裁剪放大及核算，不注册 MCP、不创建子代理。后端负责输入转换、工具作用域、结果校验、Pillow 标注和 ReportLab PDF 导出：正确为红勾，错误为红叉，位置明确的不确定题为黄问号。支持人工改判、重新框选和多页答卷下载。

## 启动

```bash
./start.sh              # 构建并启动，就绪后打印访问地址
./start.sh stop         # 停止；另有 restart / logs / status
./start.sh local        # 不用 Docker，用本机 Python 直接运行（开发用）
```

端口、访问口令等可以写在同目录的 `.env` 里（`PORT=8001`、`APP_PASSWORD=...`、`PIP_INDEX_URL=...`）。
也可以直接用 compose：

```bash
docker compose up -d --build
# 国内网络构建慢的话：
# docker compose build --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple && docker compose up -d
```

打开 <http://localhost:8001> → 「模型设置」填写后点「测试连接」：

| 项 | DeepSeek V4.1 Flash 的填法 |
| --- | --- |
| 模型名称 | `deepseek-flash` |
| 接口地址 | `https://api.deepseek.com/anthropic`（Anthropic 兼容地址，结尾不要带 `/v1`） |
| API Key | DeepSeek 平台的 Key |

单独建库可以使用支持图片及工具调用的 Anthropic 兼容模型；新批改需要可用的 DeepSeek OCR。也可以用环境变量 `LLM_MODEL / LLM_BASE_URL / LLM_API_KEY` 预置。
数据（试卷库、批改记录、设置）都在 `grader-data` 卷里。

## 功能一览

| 模块 | 做什么 |
| --- | --- |
| **批改** | 同一学生的多份材料统一提交，点击开始才处理；实时显示任务进度；人工改判后标注图立即重画；批改后的试卷可**下载 PDF** |
| **批改队列** | 返回、切页、刷新、关闭浏览器后继续批改；侧栏显示运行数量，首页展示运行列表；随时重新进入查看进度与原图 |
| **任务中心** | 一次作业 / 测验 = 一个任务。按学生添加材料、开始批改，查看已交 / 未交 / 批改中 / 待复核，逐人下载 PDF |
| **班级管理** | 班级、花名册（批量粘贴"学号 姓名"）。解析 Agent 读出卷面姓名 / 学号后自动归档到学生，匹配不上的可手动指定 |
| **学生档案 · 成长档案** | 历次正确率曲线、知识点掌握、错因分布、错题本；学情分析 Agent 写成长评语并出"错一练三"同类练习 |
| **学情报告** | 班级或单次任务：讲评清单（按正确率排序 + 典型错误答案 + 答错学生）、知识点掌握、分层名单、需要关注的学生；AI 讲评与分层建议；导出 CSV、打印 |
| **试卷库** | 单独上传试卷建库、原图、标准答案、独立解题记录；争议题可显式人工确认；可选择已备试卷批改答题卡 |

所有统计都由已保存的批改结果实时计算（`backend/app/analytics.py`），不调用模型；只有"评语 / 讲评建议"才调用学情分析 Agent，且统计数据没变时直接返回上次生成的内容。
计分口径：正确 1、部分正确 0.5、错误 0，**待复核的题不计入**，老师改判后才计入。

参考主流智慧作业产品和学校实践后加入的点：班级共性错题讲评、个人知识画像与错题本、错一练三、分层名单、需关注学生预警、提交率跟踪、保留人工复核与改判。

## 输入与单 Agent 任务

选择或拖入文件只会加入待开始列表，可追加、移除或指定「试卷 / 标准答案 / 学生作答」用途。最多 20 个文件，单个 40MB，合计 200MB，总计 40 页，PDF 在渲染前预检页数。

- **仅解题并存入试卷库**：上传试卷及可选老师答案，不需要学生作答。试卷库中也有「上传试卷建库」入口。
- **批改学生作答**：上传一位学生的多页作答及可选试卷、老师答案；只有答题卡时应选择已备试卷。关联作业已绑定试卷时使用该试卷。
- 文件用途以用户指定为准；自动模式由主 Agent 根据内容判断。发现多位学生时要求拆分。
- 上传的老师答案与 AI 解题结果分别保存；发生冲突时转人工确认，其他题继续处理。

一个 Agent 一次收到全部上传页预览、全分辨率原图路径、用户文字及必要的存档参考图。已选试卷按 ID 和版本绑定，已有题干不要求重复输出；与上传页相同的参考图不重复发送。

## 执行方式

后端只把 PDF / 图片转换为原图，不执行 OCR 或预先分类。Agent 自己根据原图和 requested_role 识别材料用途，然后在同一会话内自主看图、独立解题、核算和复核。

完整 Prompt 原文保存在 `backend/app/exam_grading_prompt.md`；`prompts.SINGLE_SUBMISSION` 追加应用字段、题号层级、老师答案处理、原图坐标及输出 JSON 格式。模型输出材料、题目、解题结果、判分和答案框，后端校验并保存，生成标注图和 PDF。

SDK 开放 `Read` 与 `Bash`，不配置 MCP 或子代理。Read 仅能读取本次上传/参考原图及裁图片；Bash 仅能执行输入给出的裁图或安全算术命令，不能运行任意 shell 命令。工具作用域由 PreToolUse Hook 检查，不编排模型认知步骤。[官方 SDK 参考](https://code.claude.com/docs/en/agent-sdk/python)。

动态裁图命令返回裁图片路径、原图像素框和归一化框，Agent 再 Read 查看，返回全页核对；最终坐标始终对应上传原图。默认最多 200 轮，可用 `EXAM_AGENT_MAX_TURNS` 调整。轮数用于同一个 Agent 的工具往返，不代表启动多个 Agent。不会因 JSON 解析失败自动重跑整份任务。

新 AI 解题结果标记为 `ai_solved`（AI 独立解题），不伪称另一位审核员已复核。老师答案冲突、缺项或看不清时保留待确认；若区域可以确认，会标黄问号。人工改判后直接重绘，不调用模型。

题号遵循原卷大题/小题结构，例如 `1.1、1.2、2.1、2.2` 或 `17(1)`；旧库内部 ID 保持稳定，用 question_label 显示卷面题号，避免答案串题。

## 接口与产物

`POST /api/submissions` 继续接收 `file` 或 `files`、`file_roles` 和 `answer_key`，新增：

| 字段 | 含义 |
| --- | --- |
| `mode` | `grade`（默认）或 `prepare`（仅建库） |
| `paper_id` | 批改所使用的已备试卷，可省略 |

新批改统一使用 `vision`。旧客户端提交的 `deepseek_ocr` 参数只做兼容并转换为视觉模式，不会调用 OCR。支持任何配置正确、具备图片和工具调用能力的 Anthropic 兼容模型；建库不关联学生、作业或已备试卷。

状态和结果包含 `mode`、`workflow_version=2`、`execution_mode=vision_agent`、`paper_id`。建库复用相同的状态、SSE 和失败重试接口，完成后进入试卷详情，不产生学生成绩。

新任务保留原件、页图、`materials.json`、`layout.json`、`answer-solution.json`、`grading.json`、`verified.json` 和 `result.json`；动态裁图在任务自己的 `agent-workdir/views` 中。试卷库保留题目、答案、参考原图和人工确认记录。历史 OCR 工件仅用于读取旧结果，不再发起识别请求。

## 后台批改与进度

上传成功后，批改由服务端独立执行，页面上的「返回」只关闭进度订阅。可以继续上传其他作业，
从侧栏「批改队列」、首页的「正在批改」或任务中心的队列重新进入；详情地址可在刷新后恢复。
后台完成不会抢占当前页面。预处理完成后即可查看原图，无需等待判分完成。

右侧合并显示「理解、解题与批改」，不虚构单次推理内部各步骤的耗时；各阶段可展开/折叠，保留页数、题数和调用耗时记录；展开「模型原始输出」可按页或批次查看各次调用的生成文本，并行输出不会混在一起。
模型内部思考只显示活动状态，不展示推理正文；只有通过后端校验的最终 JSON 才参与业务处理。
结果里的「耗时与模型调用」可查看阶段耗时、模型等待名额、首个输出、总调用时间和可用 token 用量。
各阶段可能并行，阶段耗时不能直接相加当作总时间。

主 Agent 会话默认最多等待 **30 分钟**（`AGENT_TIMEOUT_S=1800`）。等待会话并发名额不占用这 30 分钟；超时或达到轮数上限时记录为失败，不能作为已完成结果。
可通过环境变量调整，修改后需重启服务；Docker 部署需重新创建容器以载入环境配置。

任务快照和进度日志保存在每份记录的 `job.json` 与 `events.jsonl`。服务重启后，未完成任务标为「已中断」，
可点击「重试」使用原件和原输入创建新任务；原件、输入配置与答案版本仍一致时，复用已经校验的审核检查点。不会自动重启付费调用。任务快照保留模型配置但不保存 API Key，重试使用当前 Key。
本实现使用单进程 Uvicorn；不要配置多个 worker 同时读写这一份数据目录。

## 视觉定位与卷面标记

Agent 返回每题的 `page`、`answer_bbox` 和 `position_confidence`。坐标为对应原图 0–1000 的归一化坐标；裁图必须映射回原图。后端检查页码、范围、置信度和答案区重叠，定位置信度达到 70% 时接受，低于 70% 时拒绝。位置可靠时在答案附近画红勾、红叉、黄问号，不覆盖答案框；位置无法确认或无落笔空间时保留人工框选。

标注保留原图像素尺寸与 DPI，PDF 使用 ReportLab 嵌入原图，保持学生作答页顺序。只有参考用途的原题、标准答案页不混入学生答卷 PDF。人工改判自动切到对应文件的标注页；未知分值时改判不会沿用过期总分。

## 试卷版本与缓存

- 文件缓存区分工作流版本、建库/批改模式、材料内容与用途、班级/作业/学生，以及选定试卷的答案版本。改判归档或修改答案后不能返回过期结果。
- 复用的标准答案必须是审核通过或人工确认的版本。新增老师参考答案时，重新审核受影响答案。
- 老师修改答案会增加版本，清除旧答案的等价写法；只修改知识点也会更新试卷版本。
- 旧记录继续可查看和下载，但未经新流程审核的旧结果不会作为新上传的缓存直接返回。旧试卷在新流程使用时补审核，人工确认答案予以保留。
- 同卷匹配保留数学结构检查，数字、运算符、括号或变量变化时不能套用原答案。
- 未明确选卷时，自动复用还要求原题图片一致，避免同题干不同配图套用旧答案；扫描件不同可选择已备试卷。重新批改优先使用试卷库里老师最新确认的答案。

## 本地开发 / 不花钱跑通流程

```bash
pip install -r backend/requirements.txt
python tests/make_sample.py sample.png
(cd tests && uvicorn mock_llm:app --port 9911) &
(cd backend && DATA_DIR=./data uvicorn app.main:app --port 8001)
# 模型设置接口地址填 http://127.0.0.1:9911，Key 填 test-only。模拟模型只返回固定合成样例结果。
```

试卷匹配除了题干相似度，还要求题干里的数字序列完全一致（短试卷和题干指纹命中也要检查）：只改了数字的 A/B 卷不会被当成同一套；
单道题的数字和试卷库里不一致时，这道题不套用答案，转人工复核。

## 注意

- API Key 以明文保存在数据卷的 `settings.json` 里。默认没有登录；设置环境变量 `APP_PASSWORD` 后访问需要口令（HTTP Basic，用户名随意）。
  即便设置了口令，也建议只在本机或内网使用，对外请放在 HTTPS 反向代理后面。
- 系统里有学生姓名、学号和成绩，属于个人信息，请按学校的数据管理要求保管数据卷。
- 数据存成 JSON 文件，统计时会扫描全部批改记录，适合单个老师或一个年级的量（几千份以内）；更大规模需要换成数据库。
- `MAX_PARALLEL_JOBS`（默认 2）控制同时批改的份数，受模型接口的并发限额约束。
- `MAX_PARALLEL_MODEL_CALLS`（默认 3）限制顶层模型会话并发；同一 Agent 会话中的工具往返不额外启动 Agent，任务并发还受 `MAX_PARALLEL_JOBS` 限制。
- 试卷内容会发送到你配置的模型服务商。
- AI 独立解题仍可能出错；有争议的答案会保留双方意见，需老师确认。

# A道工作台 · AI 作业批改与学情分析

每组上传材料由一个持续的主 Agent 会话处理。先用 **DeepSeek OCR** 识别全部上传材料，将文字块和坐标与原图一起传给主 Agent、**答案审核 Sub Agent** 和 **学生批改 Sub Agent**。主 Agent 独立解题，两个子 Agent 分别审核标准答案和批改学生作答，最后由程序校验答案位置并绘制 ✓ / ✗ / ½。

支持先上传试卷和可选参考答案，点击「开始建库」；也可以直接添加一位学生的作答，点击「开始批改」。争议答案等待人工确认，无法定位的题保留判分、不自动落笔。模型默认使用 DeepSeek Flash，主 Agent 和子 Agent 继承同一模型配置，推理强度为 high。

## 启动

```bash
./start.sh              # 构建并启动，就绪后打印访问地址
./start.sh stop         # 停止；另有 restart / logs / status
./start.sh local        # 不用 Docker，用本机 Python 直接运行（开发用）
```

端口、访问口令等可以写在同目录的 `.env` 里（`PORT=8001`、`APP_PASSWORD=...`、`PIP_INDEX_URL=...`）。
也可以直接用 compose：

```bash
docker compose up -d --build
# 国内网络构建慢的话：
# docker compose build --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple && docker compose up -d
```

打开 <http://localhost:8001> → 「模型设置」填写后点「测试连接」：

| 项 | DeepSeek V4.1 Flash 的填法 |
| --- | --- |
| 模型名称 | `deepseek-flash` |
| 接口地址 | `https://api.deepseek.com/anthropic`（Anthropic 兼容地址，结尾不要带 `/v1`） |
| API Key | DeepSeek 平台的 Key |

单独建库可以使用支持图片及工具调用的 Anthropic 兼容模型；新批改需要可用的 DeepSeek OCR。也可以用环境变量 `LLM_MODEL / LLM_BASE_URL / LLM_API_KEY` 预置。
数据（试卷库、批改记录、设置）都在 `grader-data` 卷里。

## 功能一览

| 模块 | 做什么 |
| --- | --- |
| **批改** | 同一学生的多份材料统一提交，点击开始才处理；实时显示 Agent 进度；人工改判后标注图立即重画；批改后的试卷可**下载 PDF** |
| **批改队列** | 返回、切页、刷新、关闭浏览器后继续批改；侧栏显示运行数量，首页展示运行列表；随时重新进入查看进度与原图 |
| **任务中心** | 一次作业 / 测验 = 一个任务。按学生添加材料、开始批改，查看已交 / 未交 / 批改中 / 待复核，逐人下载 PDF |
| **班级管理** | 班级、花名册（批量粘贴"学号 姓名"）。解析 Agent 读出卷面姓名 / 学号后自动归档到学生，匹配不上的可手动指定 |
| **学生档案 · 成长档案** | 历次正确率曲线、知识点掌握、错因分布、错题本；学情分析 Agent 写成长评语并出"错一练三"同类练习 |
| **学情报告** | 班级或单次任务：讲评清单（按正确率排序 + 典型错误答案 + 答错学生）、知识点掌握、分层名单、需要关注的学生；AI 讲评与分层建议；导出 CSV、打印 |
| **试卷库** | 单独上传试卷建库、原图、标准答案、独立审核记录；争议题可显式人工确认；可选择已备试卷批改答题卡 |

所有统计都由已保存的批改结果实时计算（`backend/app/analytics.py`），不调用模型；只有"评语 / 讲评建议"才调用学情分析 Agent，且统计数据没变时直接返回上次生成的内容。
计分口径：正确 1、部分正确 0.5、错误 0，**待复核的题不计入**，老师改判后才计入。

参考主流智慧作业产品和学校实践后加入的点：班级共性错题讲评、个人知识画像与错题本、错一练三、分层名单、需关注学生预警、提交率跟踪、保留人工复核与改判。

## 输入与 Agent 分工

选择或拖入文件只会加入待开始列表，可追加、移除或指定「试卷 / 标准答案 / 学生作答」用途。最多 20 个文件，单个 40MB，合计 200MB，总计 40 页，PDF 在渲染前预检页数。

- **仅解题并存入试卷库**：上传试卷及可选老师答案，不需要学生作答。试卷库中也有「上传试卷建库」入口。
- **批改学生作答**：上传一位学生的多页作答及可选试卷、老师答案；只有答题卡时应选择已备试卷。关联作业已绑定试卷时使用该试卷。
- 文件用途以用户指定为准；自动模式由主 Agent 根据内容判断。发现多位学生时要求拆分。
- 上传的老师答案与 AI 解题结果分别保存；发生冲突时转人工确认，其他题继续处理。

主 Agent 先获得完整材料目录与共享 OCR，再通过任务内的 `read_page` 工具一起读取图片和本页 OCR。两个子 Agent 各自在自己的上下文读取原图，不能依赖继承主 Agent 的图片。

## 执行流程

```text
保存原件 → 预处理 PDF / 图片
  → DeepSeek OCR：先识别全部材料，缓存文字块、编号与坐标
  → 主 Agent：理解材料、提取完整题目、独立解题并提交答案草稿
  → answer-reviewer 子 Agent：读取原题、独立验算、提交逐题审核
  → 保存试卷和审核记录；建库模式到此完成
  → student-grader 子 Agent：读取学生原图及共享 OCR，提交作答、逐题判定及答案块编号
  → 主 Agent：检查和补充每题实际对应的 OCR 文字块
  → 后端：校验文字块、换算像素位置、绘制符号及归档
```

通过 `ClaudeAgentOptions.agents` 注册两个 `AgentDefinition`，由原生 `Agent` 工具调用。主 Agent 使用一个持续的 `ClaudeSDKClient` 会话。只开放原生 Agent 和本次任务的 MCP 工具，不开放 Bash 或任意文件读写。

后端 Hook 检查真实调用者：审核结果只能由审核员提交，学生批改结果只能由批改员提交；阶段产物绑定题目与答案版本。未审核、版本过期或输出不完整时不能继续。模型最终回复「已完成」不能代替有效产物。

AI 答案允许一次修正及重新审核，仍有分歧则待确认。老师可在试卷库修改答案，或不修改内容直接点击「确认当前答案」，再对已有记录点击「重新批改」。

## 接口与产物

`POST /api/submissions` 继续接收 `file` 或 `files`、`file_roles` 和 `answer_key`，新增：

| 字段 | 含义 |
| --- | --- |
| `mode` | `grade`（默认）或 `prepare`（仅建库） |
| `paper_id` | 批改所使用的已备试卷，可省略 |

新批改统一使用 `deepseek_ocr`；不再接受新任务的 `vision` 模式。建库在已配置 DeepSeek OCR 时也先识别材料，不执行学生批改或标注，也不能关联班级、作业或学生。

状态、事件和结果包含 `mode`、`workflow_version=2`、`paper_id`。建库复用相同的状态、SSE 和失败重试接口，完成后进入试卷详情，不产生学生成绩。

每次任务保留 `materials.json`、`layout.json`、`answer-draft.json`、`answer-review.json`、`grading.json`、OCR 原始响应及 `ocr.json`、`verified.json` 和最终 `result.json`。试卷库保留 `paper.json`、`answers.json`、`paper.md`、参考原图及其 OCR，答案逐题记录来源与审核状态。

## 后台批改与进度

上传成功后，批改由服务端独立执行，页面上的「返回」只关闭进度订阅。可以继续上传其他作业，
从侧栏「批改队列」、首页的「正在批改」或任务中心的队列重新进入；详情地址可在刷新后恢复。
后台完成不会抢占当前页面。预处理完成后即可查看原图，无需等待判分完成。

右侧每个阶段可展开/折叠，保留页数、题数、工具调用、重试和耗时记录；展开「模型原始输出」可按页或批次查看各次调用的生成文本，并行输出不会混在一起。
模型内部思考只显示活动状态，不展示推理正文；只有通过后端校验的工具提交才参与业务处理。
结果里的「耗时与模型调用」可查看阶段耗时、模型等待名额、首个输出、总调用时间和可用 token 用量。
各阶段可能并行，阶段耗时不能直接相加当作总时间。

主 Agent 会话默认最多等待 **30 分钟**（`AGENT_TIMEOUT_S=1800`），包含会话内的子 Agent 和工具调用。等待会话并发名额不占用这 30 分钟；超时或达到轮数上限时记录为失败，不能作为已完成结果。
可通过环境变量调整，修改后需重启服务；Docker 部署需重新创建容器以载入环境配置。

任务快照和进度日志保存在每份记录的 `job.json` 与 `events.jsonl`。服务重启后，未完成任务标为「已中断」，
可点击「重试」使用原件和原输入创建新任务；原件、输入配置与答案版本仍一致时，复用已经校验的审核检查点。不会自动重启付费调用。任务快照保留模型配置但不保存 API Key，重试使用当前 Key。
本实现使用单进程 Uvicorn；不要配置多个 worker 同时读写这一份数据目录。

## OCR 定位与卷面标记

新批改在开始前检查 DeepSeek OCR 是否可用。图片预处理后、主 Agent 启动前，后端对全部上传页调用 `POST /v1/tools/ocr`，使用 `rich_layout_recognition`，最多同时识别 3 页。文字块、页内唯一编号和坐标通过 `get_state` / `read_page` 共享给主 Agent 和两个子 Agent；`ocr_page` 工具直接复用已有结果。OCR 按页计费，处理试卷、参考答案及学生作答等全部上传材料。未配置 OCR 的其他模型仍可单独建库并读取原图。

原始响应单独保存。截断、接口失败或没有可用文字块时，保留已完成的判分，显示位置待确认。对暂时性的限流或服务错误有限重试。

批改子 Agent 用 `answer_block_ids` 同时提交学生答案对应的文字块，主 Agent 可补充或修正。后端检查页码、编号、答案文字片段、重复占用和坐标；一个文字块匹配失败不影响其他有效题，后续空列表不清除已定位结果。坐标使用 OCR 返回的 0–1000 归一化值，多块答案取组合边界。禁止自行猜坐标，也不回退到题干旁标记。

正确、错误、部分正确在可靠答案位置旁绘制 ✓ / ✗ / ½；争议题、无可靠位置或没有可用标注空间的题不自动落笔。原题和参考答案页只供查看，下载 PDF 仅包含学生作答页。已定位的待复核题人工改判后立即绘制；未定位时可点击「框选答案位置」，在原图拖框保存后绘制。旧任务会复用已保存的 OCR 和 Agent 选块记录修复标记，并保留原结果备份及人工判定，不重新请求模型或 OCR。

## 试卷版本与缓存

- 文件缓存区分工作流版本、建库/批改模式、材料内容与用途、班级/作业/学生，以及选定试卷的答案版本。改判归档或修改答案后不能返回过期结果。
- 复用的标准答案必须是审核通过或人工确认的版本。新增老师参考答案时，重新审核受影响答案。
- 老师修改答案会增加版本，清除旧答案的等价写法；只修改知识点也会更新试卷版本。
- 旧记录继续可查看和下载，但未经新流程审核的旧结果不会作为新上传的缓存直接返回。旧试卷在新流程使用时补审核，人工确认答案予以保留。
- 同卷匹配保留数学结构检查，数字、运算符、括号或变量变化时不能套用原答案。
- 未明确选卷时，自动复用还要求原题图片一致，避免同题干不同配图套用旧答案；扫描件不同可选择已备试卷。重新批改优先使用试卷库里老师最新确认的答案。

## 注意

- API Key 以明文保存在数据卷的 `settings.json` 里。默认没有登录；设置环境变量 `APP_PASSWORD` 后访问需要口令（HTTP Basic，用户名随意）。
  即便设置了口令，也建议只在本机或内网使用，对外请放在 HTTPS 反向代理后面。
- 系统里有学生姓名、学号和成绩，属于个人信息，请按学校的数据管理要求保管数据卷。
- 数据存成 JSON 文件，统计时会扫描全部批改记录，适合单个老师或一个年级的量（几千份以内）；更大规模需要换成数据库。
- `MAX_PARALLEL_JOBS`（默认 2）控制同时批改的份数，受模型接口的并发限额约束。
- `MAX_PARALLEL_MODEL_CALLS`（默认 3）限制顶层模型会话并发；原生子 Agent 在各自会话内调用，实际服务端请求并发还受 `MAX_PARALLEL_JOBS` 和子 Agent 执行影响。
- 试卷内容会发送到你配置的模型服务商。
- 独立审核仍可能出错；有争议的答案会保留双方意见，需老师确认。
